# v0.15.1：iOS 背景上傳

現在 iPhone 和 iPad 上傳時，`TransferPanel` 會一直擋在畫面中間，雖然底下的介面還能操作。使用者希望：

1. 上傳在 App 內的背景進行，不擋畫面。
2. 離開 App 後也能繼續上傳。

Mac 的行為不變：File > Import… 和拖放上傳還是用中間的面板。下載（分享）也不變，iOS 上仍然用中間的面板，因為分享得等下載完。

## 使用者選定的樣子

在 Select 和 ⋯ 的左邊多一顆圓形按鈕，按鈕外圈就是進度。點下去是一個小 popover：

- 「Uploading 3 of 10」
- 一條進度條
- Cancel

上傳完成後按鈕自動消失。概念和 Safari 下載、App Store 下載一樣。

## 1. Library：上傳和下載分開

改 `ImmichViewer/Core/Library.swift`。

現在上傳和下載共用 `transfer`、`transferStep`、`transferIsUpload`。上傳不再擋畫面之後，使用者可以邊上傳邊分享，兩者就會互相覆蓋。所以要拆開：

- `transfer` 和 `transferStep` 只給下載用。刪掉 `transferIsUpload`。
- 新增上傳專用的狀態：
  ```swift
  /// The upload under way (one at a time); cancel it to stop. `uploadStep` is the item it is on, from 1.
  private(set) var upload: Progress?
  private(set) var uploadStep = 0
  ```
- `upload(count:album:item:)` 改用 `upload`、`uploadStep`，其他邏輯不動：失敗清單、相簿、`refresh()` 都照舊。

## 2. 進度面板

改 `ImmichViewer/Shared/Editing.swift` 裡的 `TransferPanel`。

- 在 macOS 上顯示 `library.upload ?? library.transfer`。
  - 文字依照顯示的是哪一個，選「Uploading \(step) of \(total)」或「Downloading …」。
  - step 分別取 `uploadStep` 或 `transferStep`。
  - 一個時間只會有一個，因為 Mac 的匯入和拖放仍然規定同一時間只能有一個傳輸。
- 在 iOS 上只顯示 `library.transfer`，也就是下載。
- 動畫的 `value` 跟著改。

Mac 的 `canDrop`（`ImmichViewerApp.swift:279`）和 File > Import… 的 disabled 條件：凡是原本判斷 `library.transfer == nil` 的地方，改成 `library.transfer == nil && library.upload == nil`。先 grep `transfer` 找出所有的地方。

## 3. iOS 工具列的上傳按鈕

在 `ImmichViewer/iOS/` 新增 `UploadButton.swift`，並放進 Xcode 專案。專案用的是 PBXFileSystemSynchronizedRootGroup 或手寫的 file refs，先看清楚是哪一種，照現有的 iOS 檔案加入方式做。

```swift
/// In the top bar while an upload runs: a ring filling with its progress; tap for the count and Cancel.
struct UploadButton: View {
    @Environment(Library.self) private var library
    @State private var shown = false
    …
}
```

- 按鈕的標籤是一個圈，畫法用自訂的 `ProgressViewStyle`：
  - `ProgressView(progress).progressViewStyle(Ring())`。SwiftUI 會自己觀察 `Progress`，`configuration.fractionCompleted` 會跟著更新。
  - 底圈：`Circle().stroke(.secondary.opacity(0.3), lineWidth: 2.5)`。
  - 前景：`Circle().trim(from: 0, to: fraction).stroke(.tint, style: StrokeStyle(lineWidth: 2.5, lineCap: .round)).rotationEffect(.degrees(-90))`。
  - 中間放 `Image(systemName: "arrow.up")`，字級 `.caption.weight(.bold)`。
  - 大約 22×22 pt，和工具列其他圖示一樣大。
  - 要有 `.accessibilityLabel("Uploading")` 和 `.accessibilityValue`（百分比）。
- 點下去打開 `.popover(isPresented: $shown)`，加 `.presentationCompactAdaptation(.popover)`，iPhone 上才會是 popover 而不是 sheet。內容和 TransferPanel 一樣：
  - `Text("Uploading \(step) of \(total)")`，用 `.headline`、`.monospacedDigit()`。
  - `ProgressView(progress).labelsHidden()`。
  - `Button("Cancel", role: .cancel) { progress.cancel() }`。
  - `padding(20)`，寬度大約 260。
- `library.upload` 變成 nil 時，`shown = false`。

放置位置：`PhoneTimeline.swift` 的 `.toolbar` 裡，在 Select/Cancel 那顆之前。

- 加 `if library.upload != nil { ToolbarItem(id: "upload", placement: .primaryAction) { UploadButton() } }`，後面接一個 `ToolbarSpacer(.fixed, placement: .primaryAction)`。這樣它是自己一顆玻璃，不會和 Select 黏在一起。
- 包在 `withAnimation`／`.animation` 裡，讓它淡入淡出。
- PhoneTimeline 是所有照片頁共用的，所以 Library、相簿、人物等頁面都看得到。

iOS 上原本判斷 `library.transfer` 的地方都改成判斷 `library.upload`：

- `PhoneTimeline.swift:46` 的 `canDrop`。
- `:124`，Upload from Photos… 的 `.disabled`。

上傳中只禁止再開一次上傳，下載（分享）不受影響。

## 4. 離開 App 後繼續：BGContinuedProcessingTask（iOS 26）

App 最低支援 iOS 26，所以直接用，不必另外檢查可用性。

用到的 API：

- `BGContinuedProcessingTaskRequest(identifier:title:subtitle:)`
- `BGTaskScheduler.shared.register(forTaskWithIdentifier:using:launchHandler:)`：continued processing 的任務可以在 App 啟動之後才註冊。
- `task.updateTitle(_:subtitle:)`
- `task.progress`：必須持續回報，否則會被判定為卡住而過期。
- `task.expirationHandler`：使用者在系統介面按停止也會觸發。
- `task.setTaskCompleted(success:)`

### Info.plist

在根目錄的 `Info.plist`（Mac 和 iOS 共用，Mac 會忽略）加上：

```xml
<!-- iOS: an upload carries on after leaving the app (BGContinuedProcessingTask, with the system's progress) -->
<key>BGTaskSchedulerPermittedIdentifiers</key>
<array>
    <string>$(PRODUCT_BUNDLE_IDENTIFIER).upload.*</string>
</array>
```

提交時如果出現 `notPermitted`，再試著加 `UIBackgroundModes` → `processing`，並把原因寫進註解。

### 程式

新增 `ImmichViewer/iOS/BackgroundUpload.swift`，或者直接寫在 Library 的 `#if os(iOS)` 區塊裡，選比較少程式碼的做法。

- 在 `upload(count:album:item:)` 開始時（iOS），呼叫 `let background = BackgroundUpload.start(progress: progress, count: count)`；結束時（`defer`）呼叫 `background?.finish(success: !progress.isCancelled)`。
- `start` 要做的事：
  1. 識別碼是 `"\(Bundle.main.bundleIdentifier!).upload.\(UUID().uuidString)"`。
  2. 用這個識別碼註冊 handler。handler 拿到 `BGContinuedProcessingTask` 之後：
     - 存起來。
     - `task.progress.totalUnitCount = 1000`。
     - 設 `expirationHandler = { progress.cancel() }`，要切回 main actor 再取消。
     - 如果這時已經結束，立刻 `setTaskCompleted`。
  3. 送出請求：`title` 是「Uploading to Immich」，`subtitle` 是「0 of \(count)」，`strategy = .fail`。
     - 失敗就安靜略過，只寫進 log。這時上傳照樣在前景進行，只是離開 App 後會停。
- 回報進度：
  - 用 KVO 觀察我們自己的 `progress` 的 `fractionCompleted`：`observe(\.fractionCompleted)`。
  - 收到更新時，設 `task.progress.completedUnitCount = Int64(fraction * 1000)`。
  - `uploadStep` 改變時（Library 端），呼叫 `task.updateTitle(title, subtitle: "\(step) of \(count)")`。
  - 這些都要處理執行緒：KVO 回呼可能在背景執行緒，`BGTask` 本身是 thread-safe 的。
- `finish`：
  - 如果 task 已經拿到，呼叫 `task.setTaskCompleted(success:)`。
  - 如果還沒拿到，記下「已結束」，handler 一來就馬上 complete。
  - 移除 KVO observer。
- Handler 可能在任意 queue 被叫用（`using: nil`），共享的狀態用一個 lock 或 actor 保護，寫得越簡單越好。

字串要新增到 `Localizable.xcstrings`，並翻成 zh-Hant 和 zh-Hans：

- Uploading to Immich：上傳到 Immich／上传到 Immich
- \(step) of \(total)：第 3 張，共 10 張／第 3 张，共 10 张
- Uploading：正在上傳／正在上传

已經存在的「Uploading \(step) of \(total)」直接沿用。

## 驗證（另一個 Sonnet）

只用已開機的 iOS 27 模擬器：iPhone 17 Pro、iPad Pro 11-inch (M5)。只連 scratchpad 的假伺服器 2303，啟動方式照 summary 的 SIMCTL_CHILD_… 指令。**不能連真伺服器，也不能從 keychain 讀金鑰。**

1. 兩個平台都要 build：iOS 模擬器，以及 Mac（`-derivedDataPath build`）。`Tests/main.swift` 照現有方式跑過。
2. 上傳要慢到看得出過程，可以在假伺服器的 POST assets 加 sleep，或者拖放大檔案。
   - 確認畫面中間沒有面板。
   - 確認 Select 左邊有圈，而且圈會跟著進度填滿。
   - 點開 popover，數字和 Cancel 都要正確；按 Cancel 會停止上傳。
3. 上傳中分享一張照片，下載面板照常出現，上傳不受影響。
4. 上傳中按 Home 離開 App：
   - 看假伺服器的 log，確認上傳繼續進行。
   - 看系統有沒有顯示進度。
   - 回報 `BGTaskScheduler.submit` 是否成功；模擬器可能不支援，要如實回報。
5. 錄影或截圖，比對圈的大小、位置和其他工具列按鈕是否一致。
